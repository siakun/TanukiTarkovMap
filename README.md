> **Escape from Tarkov용 인게임 미니맵 오버레이 툴입니다.<br>스크린샷을 찍으면 좌표를 감지해 현재 위치를 미니맵에 표시합니다.**

게임 위에 항상 떠 있는 창으로 [tarkov-market.com](https://tarkov-market.com/pilot)의 인터랙티브 맵을 띄우고, 인게임 스크린샷에 기록된 좌표로 현재 위치를 실시간 표시합니다. Online은 사이트 지도 위에, Local은 앱에 담긴 지도에 현재 위치와 방향을 표시합니다. 알트탭 없이 단축키 한 번으로 맵을 확인할 수 있습니다.

## 설치

1. [Releases 페이지](https://github.com/siakun/TanukiTarkovMap/releases/latest)에서 최신 Setup 설치 파일(`TanukiTarkovMap-Setup-<버전>-x64.exe`)을 내려받습니다.
2. 실행해 설치하면 이후 업데이트는 자동으로 적용됩니다. 설정에서 자동 업데이트를 끄거나 원하는 버전으로 되돌릴 수도 있습니다.

설치 없이 쓰고 싶다면 같은 페이지의 포터블 버전(`TanukiTarkovMap-Portable-<버전>-x64.zip`)을 내려받아 압축을 풀고 실행합니다. 포터블은 설치 절차가 없어 아래 요구 사항의 VC++ 재배포 패키지를 직접 깔아야 합니다.

> **요구 사항**: Windows 10/11 (x64), [Microsoft Visual C++ 2015-2022 재배포 패키지(x64)](https://aka.ms/vs/17/release/vc_redist.x64.exe)
>
> 재배포 패키지는 내장 브라우저(CefSharp)가 쓰는 런타임입니다. Setup 설치 파일은 없으면 설치 과정에서 알아서 깔아 주므로 따로 준비할 것이 없고, 포터블만 직접 설치가 필요합니다. 없이 실행하면 `CefSharp.Core.Runtime.dll`을 불러오지 못했다는 오류로 앱이 시작하지 않습니다.
>
> **안전성**: 게임 메모리를 읽거나 게임 프로세스에 개입하지 않습니다. 이 앱이 읽는 것은 스크린샷 파일명(이미지 내용이 아니라 이름에 담긴 좌표만)과 입장한 맵이 기록된 게임 로그 두 가지뿐이며, 게임 파일을 수정하지 않습니다. 자세한 원리는 [프로젝트 배경](#프로젝트-배경)을 참고하세요.

## 사용법

1. TanukiTarkovMap을 실행합니다. 게임의 스크린샷 폴더는 자동으로 감지되며, 필요하면 설정 창에서 직접 지정할 수 있습니다.
2. 게임을 시작하면 입장한 맵으로 자동 전환됩니다.
3. 게임 중 단축키(기본 `F11`, 설정에서 변경 가능)로 맵 창을 켜고 끕니다.
4. 인게임 스크린샷 키(기본 `PrtScn`)를 누르면 Online이나 Local에 현재 위치와 방향이 갱신됩니다. Online 위치 표시 안내가 나타나면 상단 바에서 Local로 전환해 주세요.

상단 바에서 보기 모드를 고릅니다. `Online`은 tarkov-market.com을 지도 위주로 정리하고 현재 위치와 방향을 겹쳐 표시합니다. `Local`은 앱에 담긴 지도로 현재 위치와 방향을 표시합니다. `Origin`은 사이트를 앱의 변경 없이 그대로 엽니다. `Origin`에서는 `PMC`/`SCAV`와 `UI 요소 숨기기`가 적용되지 않습니다. 고른 모드는 다음에 실행할 때도 유지됩니다.

창 표시/숨김 단축키는 미니맵 창 전체를 트레이로 숨기거나 다시 표시하며, 앱을 종료하지 않습니다. 위치 갱신에는 게임의 Screenshot 키를 사용합니다. 한 모니터에서 게임 위에 계속 띄우려면 상단 핀(항상 위)을 켜 주세요.

> **Steam 사용자 주의**: Steam의 `F12` 스크린샷은 Steam 오버레이 기능이라 좌표가 기록되지 않습니다. 반드시 게임 자체 설정(Controls)의 Screenshot 키를 써야 하며, 기본 `PrtScn`이 동작하지 않는다는 보고가 있으니 그 경우 다른 키로 재바인딩하세요.

설정 창에서 단축키, 투명도, UI 표시 여부, 자동 맵 전환, 스크린샷 자동 정리, 업데이트 방식을 바꿀 수 있습니다. 맵 타일이 쌓이는 브라우저 캐시가 얼마나 되는지 확인하고 비우는 것도 같은 창에서 합니다. 문제가 생기거나 건의할 내용이 있으면 [GitHub Issues](https://github.com/siakun/TanukiTarkovMap/issues)에 남겨 주세요.

## 주요 기능

| 기능 | 설명 |
|------|------|
| 맵 오버레이 | 게임 위에 항상 표시되는 인터랙티브 맵 (Always-on-Top) |
| 실시간 위치 추적 | 인게임 스크린샷으로 Online과 Local의 위치와 방향 갱신 |
| 보기 모드 | 상단 바에서 Online(사이트와 위치 및 방향), Local(앱에 담긴 지도와 위치 및 방향), Origin(원본 사이트) 전환 |
| 자동 맵 전환 | 게임 로그를 감지해 입장한 맵으로 자동 전환 |
| 전역 단축키 토글 | 단축키(기본 `F11`) 한 번으로 맵 창 표시/숨김, 조합키와 특수키 지원 |
| 투명도 조절 | 상단 바가 숨겨지면 창이 반투명해져 게임 시야 방해를 최소화 |
| UI 정리 | Online에서 웹페이지의 불필요한 요소를 제거해 맵만 표시 |
| 군즈 최근 목격 제보 | PvE 목격 제보의 맵 표시 |
| 레이드 위치 공유 | 같은 파티로 레이드에 들어간 친구와 스크린샷 위치를 주고받아 지도에 함께 표시 (자동 연결) |
| 업데이트 관리 | 새 버전 자동 적용, 자동 업데이트 끄기, 지난 버전으로 되돌리기 |
| 화면 언어 | 기본은 Windows 표시 언어를 따르고, 설정에서 고르면 다시 시작하지 않고 바로 바뀜 |

군즈 최근 목격 제보는 기본적으로 꺼져 있으며, 설정에서 켤 수 있습니다. 군즈는 확률에 따라 스폰하므로 제보와 실제 출현이 다를 수 있습니다.

레이드 위치 공유는 개발자가 운영하는 서버에 자동으로 접속하며, 입력할 값은 없습니다. 같은 파티로 같은 레이드에 들어간 사람끼리 스크린샷 위치를 주고받고, 내 위치와 함께 게임 계정 ID가 서버로 갑니다. 혼자 들어간 레이드는 공유하지 않고, 같은 레이드의 다른 파티는 내 위치를 받지 않습니다. 친구의 이름표는 내 게임의 파티 알림이나 같은 방 파티원이 알려 준 닉네임으로 표시하고, 찾지 못하면 계정 ID 끝 네 자리로 표시합니다. 지도 왼쪽 아래에는 `InRaid: 3p (이름, 이름, 이름)`처럼 나를 포함한 공유 인원과 이름을 표시합니다. 스크린샷 전에도 표시하며 혼자 들어간 레이드, 로컬 PvE, 메뉴나 연결이 끊긴 상태에서는 숨깁니다.

## 프로젝트 배경

Escape from Tarkov은 인게임에서 스크린샷을 찍으면 파일명에 플레이어의 월드 좌표(X, Y, Z)와 카메라 회전값이 함께 기록됩니다. 개발사 Battlestate Games가 버그 리포트용으로 공식 제공하는 기능이며, 게임 메모리나 프로세스에 접근하지 않고 디스크에 저장된 파일만 읽습니다.

```
2026-09-09[14-14]_179.10, 3.29, -717.65_0, 0.70710678, 0, 0.70710678_15.67 (0).png
└ 날짜/시각 ┘     └ 위치 X, Y, Z ┘      └ 카메라 회전(쿼터니언) ┘
```

[tarkov-market.com](https://tarkov-market.com/pilot)의 Pilot 페이지는 이 좌표를 받아 맵 위에 현재 위치를 표시합니다. 다만 브라우저로 여는 웹앱은 구조적 한계가 있습니다. 게임 위에 항상 고정(Always-on-Top)하거나, 창을 반투명하게 만들거나, 전역 단축키로 토글하는 것처럼 운영체제 창을 직접 제어하는 일을 할 수 없습니다. 데스크톱 클라이언트가 필요한 이유가 여기에 있습니다.

이런 도구는 이미 여럿 있습니다. 원조는 tarkov-market.com이 공식 감지하는 [ggdiam/TarkovPilot](https://github.com/ggdiam/TarkovPilot)(.NET Framework, 트레이 전용 헬퍼)이고, 한국 커뮤니티의 [byeong1/Tarkov-Client](https://github.com/byeong1/Tarkov-Client)는 이를 Edge WebView2로 감싸 창 안에 띄웠습니다. 이 프로젝트는 byeong1 버전의 아이디어에서 출발했지만, 웹뷰 엔진을 CefSharp로 교체하고 창 제어, 좌표 동기화, 빌드 파이프라인을 처음부터 다시 설계했습니다.

## 기술적 구현

이 프로젝트의 핵심은 "웹앱이 못 하는 일을 네이티브 클라이언트가 대신하는 것"입니다. 각 기능을 어떤 문제 때문에, 어떤 방식으로 풀었는지 정리합니다.

### 1. Edge WebView2에서 CefSharp로 포팅

출발점이 된 도구는 Windows에 내장된 Edge WebView2를 썼지만, 이 프로젝트는 웹뷰 엔진을 CefSharp(Chromium Embedded Framework)로 교체했습니다. WebView2는 런타임이 사용자 환경에 의존하는 반면, CefSharp는 Chromium을 앱과 함께 배포해 환경에 독립적이고 렌더 프로세스, 스크립트 주입, 줌 같은 동작을 더 직접 제어할 수 있습니다. 페이지 로드가 시작될 때(`FrameLoadStart`)와 끝날 때(`FrameLoadEnd`)에 맞춰 스크립트를 주입하고, `JavascriptMessageReceived`로 웹에서 앱으로 오는 메시지를 받는 방식으로 통합했습니다.

### 2. 네이티브 창 제어

웹앱이 할 수 없는 OS 창 제어를 데스크톱 창에서 직접 처리합니다. 핀 고정과 반투명은 WPF 창 속성으로, 전역 단축키와 트레이 복귀처럼 WPF에 없는 동작은 P/Invoke(user32.dll)로 처리합니다.

- **Always-on-Top**: 창의 `Topmost`를 핀 버튼 상태에 바인딩해 게임 위에 고정. 트레이에서 되돌릴 때는 포커스를 빼앗지 않도록 `SetWindowPos`로 창만 올리고, 이때도 핀 상태(`HWND_TOPMOST` 또는 `HWND_TOP`)를 지킴
- **반투명 창**: 테두리 없는 투명 창(`AllowsTransparency`)의 내용 `Opacity`를 투명도 설정에 바인딩. 상단바가 숨어 있거나 투명도 슬라이더를 끄는 동안에만 적용해, 조작할 때는 불투명하게 보임
- **전역 단축키**: 저수준 키보드 훅(`SetWindowsHookEx`)으로 게임이 포커스를 가진 상태에서도 토글 동작

Win32 선언은 `PInvoke.cs`에 모았습니다. 예외로 `Program.cs`는 이미 실행 중인 창을 앞으로 가져오는 단일 인스턴스 처리에 자체 선언을 둡니다.

### 3. 실시간 좌표 동기화 (FileSystemWatcher + 자체 미니맵)

스크린샷 폴더를 `FileSystemWatcher`로 감시하고 새 파일의 이름을 현재 맵에 묶어 보관합니다. Online은 Core DLL이 파일명과 리소스 상수로 좌표를 계산하며, 사이트의 실시간 보기 상태에 맞춰 브라우저 위 WPF Canvas에 위치 원과 방향 화살표를 표시합니다. Local 미니맵은 파일명에서 좌표와 회전값을 읽어 위치와 방향을 그립니다. 두 모드는 위치 높이로 층을 선택합니다. 게임 로그도 함께 감시(`LogsWatcher`)해 플레이어가 입장한 맵으로 전환합니다.

앱은 맵별 최신 입력 하나만 유지합니다. 같은 맵에서 모드를 전환하면 마지막 위치를 이어 표시하고 다른 맵으로 이동하면 이전 위치를 종료합니다. Origin은 위치를 표시하지 않고 입력만 보관합니다. Online은 처음 보인 파일명에만 핑을 실행하며, 보기 상태를 수집하지 못하면 로그와 Local 전환 안내를 표시합니다. Local은 로딩 중 받았거나 새로고침으로 사라진 위치를 확인해 다시 전달합니다.

2026-08-17까지는 앱 안에서 ASP.NET Core Kestrel로 포트 `5123`에 WebSocket 서버를 띄우고, 사이트가 그 서버에 접속해 파일명을 받아 갔습니다. 같은 날 tarkov-market이 Pilot v2를 배포하면서 사이트가 로컬 앱 대신 자기 서버(`wss://tarkov-market.com/ws/pilot`)로만 붙게 바뀌어, 서버를 띄워도 접속하는 클라이언트가 없어졌습니다. 서버 중계 규약을 따라가려면 계정 인증까지 구현해야 하는데 `window.pilot`은 그것 없이 같은 일을 하므로, WebSocket 서버와 ASP.NET Core 의존을 걷어내고 브리지 호출로 갈아탔습니다.

2026-10-07에는 사이트가 `window.pilot`의 위치 함수와 Pilot 서비스의 위치 입력을 모두 없앴습니다. 남은 것은 사용자가 스크린샷 파일명을 붙여 넣는 "Where am i" 입력뿐이었으므로, 브리지가 화면에 렌더 중인 Vue 컴포넌트에서 그 입력의 처리기를 찾아 같은 파일명을 넘기게 했습니다. 압축된 번들의 함수 이름은 배포마다 바뀌지만 템플릿의 prop 이름은 남는다는 점을 이용했습니다.

2026-10-08에는 사이트가 지도와 내 위치를 캔버스로 그리고 방향 화살표를 PRO 사용자에게만 보여 주도록 바꾸면서, Online의 방향 표시와 위치 확인이 다시 끊겼습니다. 위치 입력 경로와 내 위치 그리기는 배포 때마다 바뀌었지만 지도의 좌표 변환은 그대로였습니다. 그래서 사이트에 위치를 넘기는 대신 앱이 위치와 방향을 직접 그리고, 사이트에서는 좌표 변환만 빌리도록 바꿨습니다.

사이트가 지도 상태를 일반 반응형 등록에서 제외하면서 기존 WeakMap 기록으로는 보기 상태를 얻지 못하게 됐습니다. 현재 Online은 Proxy 생성 시점에 필요한 상태를 기록하고, 좌표 및 방향 연산과 마커 그리기는 Core DLL과 WPF로 분리합니다. 사이트 상태에 기대는 경로이므로 Local은 독립된 위치 표시 경로로 유지합니다.

### 4. 오프라인 맵 (Local)

상단 바에서 Local을 고르면 사이트에 접속하지 않고 앱에 담긴 지도 데이터로 맵을 엽니다. 지도와 층, 선택한 진영의 추출구, 현재 위치와 방향만 남기므로 사이트가 죽어 있거나 사이트의 지도 구조가 바뀌어도 레이드에 필요한 정보가 동작합니다.

처음에는 사이트가 내려보낸 응답을 통째로 저장한 사본을 요청 가로채기로 돌려줬습니다. 동작은 했지만 사본이 압축된 번들 덩어리라 무엇이 들었는지 읽을 수 없었고, 사이트가 구조를 바꾸면 통째로 다시 받는 것 말고는 방법이 없었습니다. 지금은 사이트의 지도 문서만 수집해 SVG와 JSON으로 변환해 Core DLL에 담고, 앱에 포함한 미니맵(`viewer/`)이 사이트의 지도 화면과 같은 모양으로 그립니다. 변환한 SVG는 수집한 사이트 렌더러로 그린 결과와 층마다 픽셀로 대조하고, 좌표 변환은 사이트가 계산한 값과 비교해 검증합니다.

Local은 독립된 임시 저장 공간에서 열어 사이트(Online, Origin)의 DB와 캐시가 섞이지 않게 합니다. 모드를 전환하면 같은 맵을 새 모드로 다시 열고 Local에는 마지막 위치를 전달합니다. 앱의 확대 설정은 모든 모드에, 진영과 UI 숨김 설정은 Online과 Local에 다시 적용합니다.

### 5. 게임 로그 파싱으로 자동 맵 전환

게임은 실행할 때마다 로그 폴더(공식 런처는 `게임 폴더\Logs`, 스팀판은 `게임 폴더\build\Logs`) 아래에 새 세션 폴더를 만들고 `application.log` 등에 상태를 기록합니다. 게임 폴더는 레지스트리에서 자동 감지하며(공식 런처 -> 스팀 순), 실패하면 설정에서 직접 지정할 수 있습니다.

- **공식 런처**: `HKLM\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\EscapeFromTarkov`의 `InstallLocation` 값 (폴더가 실제 존재할 때만 채택)
- **스팀**: `HKLM\SOFTWARE\WOW6432Node\Valve\Steam`의 `InstallPath`에서 `steamapps\libraryfolders.vdf`를 파싱해 얻은 모든 라이브러리 폴더의 `steamapps\common\Escape from Tarkov`를 확인

`LogsWatcher`는 가장 최근 세션 폴더를 골라 감시하고(새 폴더가 생기면 자동으로 갈아탐), 로그 파일이 갱신될 때마다 마지막으로 읽은 위치부터 새로 추가된 줄만 이어 읽습니다(`FileShare.ReadWrite`로 열어 게임의 쓰기와 충돌하지 않음). 앱 시작 전에 이미 쌓여 있던 과거 로그로는 화면을 전환하지 않아, 지난 판의 맵으로 잘못 바뀌는 것을 막습니다.

맵 판별은 씬 로드 로그(`scene preset`) 줄에서 `path:maps/<프리셋>.bundle`의 프리셋 이름을 뽑아 합니다. 매치 생성 로그(`TRACE-NetworkGameCreate profileStatus`)의 `Location:` 값도 같은 정보를 담지만, 씬 로드 줄이 언제나 먼저 나오고 이쪽만 남는 레이드도 있어 씬 로드 줄 하나만 봅니다.

뽑아낸 프리셋 이름은 감지한 자리에서 곧바로 맵으로 해석합니다. 로그 문자열을 해석하는 코드를 `LogsWatcher` 한 곳에 묶어 두려는 것이고, 그 뒤 단계는 문자열이 아니라 맵 객체만 주고받습니다.

```
scene preset 줄 감지
  -> LogsWatcher          프리셋 이름 추출
  -> MapConfiguration     프리셋을 맵으로 해석 (등록되지 않은 값이면 여기서 중단)
  -> MapEventService      맵 변경 이벤트 발행
  -> MainWindowViewModel  SelectedMapInfo 대입 (드롭다운 수동 선택이 합류하는 지점)
  -> WebBrowserViewModel  CefSharp 주소 이동
```

맵과 프리셋의 관계는 1:N입니다. Ground Zero는 레벨 구간마다, Factory는 시간대마다 프리셋이 따로 있어서 맵 하나가 프리셋 목록을 갖는 형태로 `MapConfiguration`에 등록합니다. 목록에 없는 프리셋이 나오면 전환하지 않고 그 이름만 앱 로그에 남깁니다. 게임에 새 맵이 추가됐을 때 무엇을 등록해야 하는지 그 줄로 알 수 있습니다.

자동 전환이 `SelectedMapInfo`를 거치는 것도 의도한 부분입니다. 사용자가 드롭다운에서 맵을 고를 때와 같은 지점으로 합류시키면, 주소를 바꾸고 스크립트를 다시 주입하는 코드가 한 벌만 남습니다. 자동 전환을 끄면 이 대입만 건너뛰므로 수동 선택은 그대로 동작합니다.

레이드에 들어간 뒤에 앱을 켜면 진입 로그가 이미 지나가 있어 실시간 감지가 걸리지 않습니다. 그래서 과거 로그에서도 맵 이름만은 읽어 마지막 값을 기억해 두고, 인게임에서만 찍히는 스크린샷을 신호로 삼아 그 맵으로 보정합니다. 이미 그 맵을 보고 있으면 아무 일도 일어나지 않으므로, 정상적으로 전환된 뒤에는 스크린샷을 찍어도 화면이 흔들리지 않습니다.

이 밖에 BattlEye 초기화 로그(`BEClient inited successfully`)는 레이드 경계 신호로 삼아 스크린샷 자동 정리를 트리거합니다.

### 6. CefSharp와 JavaScript 양방향 통신

위치와 방향 표시를 수정한 뒤에는 사이트 접속 여부와 무관하게 같은 실패 조건을 자동 검사로 다시 확인합니다. 검사는 창 없는 Chromium에서 앱에 담긴 미니맵과 지도 리소스로 돌고, 설치 파일을 만들 때마다 실행합니다. 지금 사이트에서 Online의 상태 기록, 지도 맞춤과 층 선택, UI 숨김과 진영 전환이 동작하는지는 실제 사이트에 앱과 같은 스크립트를 넣는 진단 도구로 따로 확인합니다.

웹 UI를 앱에 맞게 다듬는 로직은 JavaScript로 주입합니다. 사이트에 주입하는 JavaScript와 실행 계약은 Core DLL에 EmbeddedResource로 포함합니다. Core의 `SiteControl`은 호출 순서와 진영 재시도를, `OnlineOverlay`는 사이트 응답 해석과 위치 동기화를 담당합니다. 앱은 CEF 수명과 문서 유효성 확인, WPF 표시를 맡습니다. 스크립트는 두 시점에 실행합니다. 페이지 로드가 시작될 때는 지도 상태 기록과 페이지 오류 관찰 스크립트를 먼저 주입하고, 로드가 끝나면 나머지를 `EvaluateScriptAsync`로 실행합니다(헤더와 푸터 제거, 패널 토글, 진영 필터 등). 반대로 페이지의 오류와 지도 렌더 여부는 `postMessage`로 보내 `JavascriptMessageReceived`에서 받아 앱 로그에 남깁니다. ViewModel 사이의 전달은 CommunityToolkit.Mvvm의 `WeakReferenceMessenger`가 맡습니다. C#과 JS의 경계를 메시지로 느슨하게 연결했습니다. Local 미니맵에는 주입하지 않고 미니맵이 공개한 `window.tanukiViewer`의 함수만 부릅니다. Origin은 사이트를 그대로 보여 주는 모드라 아무것도 주입하지 않습니다. 주입 여부는 페이지를 열 때 정해지므로 Online과 Origin 사이를 전환하면 지금 페이지를 다시 엽니다.

### 7. MVVM 아키텍처와 DI

코드비하인드(`*.xaml.cs`)에는 로직을 두지 않는 것을 원칙으로 합니다. 메인 창에 남은 초기화 로직은 정리 대상으로 관리합니다. UI 인터랙션은 Microsoft.Xaml.Behaviors 기반 Behavior로 분리하고(창 드래그, 트레이 최소화, 단축키 입력 캡처 등), 데이터와 비즈니스 로직은 ViewModel과 Service에 둡니다. 서비스는 Microsoft.Extensions.DependencyInjection으로 등록하고 `ServiceLocator`로 접근하며, ViewModel 사이 통신은 직접 참조 대신 Messenger로 처리해 결합도를 낮췄습니다.

### 8. 릴리스 자동화 (Velopack + GitHub Releases)

버전 태그를 붙이면 빌드와 검사, self-contained publish와 Velopack 패키징을 거쳐 GitHub Releases에 설치 파일과 업데이트 패키지를 올립니다. 이 저장소에는 릴리스마다 그 버전의 소스를 커밋 하나로 올리고 같은 이름의 태그를 붙입니다. 릴리스 본문과 설치 패키지에 들어가는 업데이트 내역은 같은 파일에서 나오며, 태그와 프로젝트 버전이 다르거나 내역이 없으면 배포를 중단합니다. 설치된 앱의 업데이트는 메인 창이 열린 뒤 새 버전을 받고 정상 종료 시 CefSharp를 정리한 다음 적용합니다.

### 9. 버전 선택과 되돌리기

자동 업데이트는 최신 버전으로만 흐릅니다. 새 버전에서 문제를 만난 사용자가 스스로 빠져나올 길이 없다는 뜻이라, 설정에서 자동 업데이트를 끄고 원하는 버전을 직접 고를 수 있게 했습니다.

여기에는 Velopack의 기본 경로를 쓸 수 없습니다. `GithubSource`는 "최신 릴리스 하나에 모든 패키지가 모여 있다"를 전제로 그 릴리스의 `releases.win.json`만 읽고 다운로드 주소도 그 안에서만 찾습니다. 이 저장소는 전체 패키지가 수백 MB라 태그마다 자기 버전만 올리므로, 기본 경로로는 최신과 그 직전까지 두 버전만 보입니다. 그래서 릴리스 목록은 GitHub Releases API로 직접 조회하고, 고른 태그 하나에 고정된 `IUpdateSource`(`GitHubReleaseSource`)를 만들어 Velopack의 다운로드, 체크섬 검증, 적용 절차에 태웁니다. 이 업데이트 코드는 다른 앱에서도 쓸 수 있도록 [Siakun.AutoUpdate](https://github.com/siakun/Siakun.AutoUpdate) 패키지로 분리했습니다.

패키지 메타데이터를 직접 조립하지 않고 릴리스가 이미 담고 있는 피드 JSON을 파싱하는 것도 이 때문입니다. Velopack은 받은 패키지의 SHA를 피드 값과 대조하는데, 손으로 만든 값에는 그 해시가 없어 검증을 통과시킬 방법이 없습니다.

위로 올라갈 때는 그 사이 버전들의 delta를 이어 붙여 받습니다. 전체 패키지는 수백 MB인데 delta는 한 개에 수백 KB라 차이가 큽니다. 되돌릴 때는 언제나 전체 패키지를 받습니다. delta는 올라가는 방향으로만 만들어지기 때문입니다. 사이 릴리스가 지워졌거나, 건너뛸 단계가 너무 많거나, delta를 다 합친 크기가 전체 패키지에 견줘 커지면 그때도 전체를 받습니다. 오래 걸릴 수 있는 작업이라 진행률을 화면에 표시합니다. 다운로드가 끝나도 프로세스를 강제로 끊지 않고, CefSharp가 쿠키와 IndexedDB 파일을 놓도록 정상 종료한 뒤 패키지를 적용합니다.

최신이 아닌 버전을 고르면 자동 업데이트를 함께 끕니다. 켜둔 채로 두면 다음 실행에서 곧바로 최신으로 되돌아가 사용자가 고른 버전이 사라지기 때문입니다.

설정의 실험적 기능에서 베타 받기를 켜면 `v0.1.1-beta`처럼 정식 출시 전 버전도 목록과 자동 업데이트 대상에 들어옵니다. 꺼두면 조회 단계에서 빠지므로 목록에 보이는 것과 자동 업데이트가 따라가는 대상이 언제나 같습니다.

이 차단은 자동 업데이트 설정이 들어간 버전부터 유효합니다. 그보다 오래된 버전으로 내려가면 그 버전의 업데이트 코드가 설정을 보지 않고 최신을 받아 오므로 거기에 머무를 수 없습니다. 이미 배포된 코드는 고칠 수 없어 설계로 막을 방법이 없고, 설정 화면에서 그 사실을 미리 알리는 것으로 대신합니다.

### 10. 레이드 위치 공유 (SignalR)

친구와 같은 레이드에 들어가도 앱은 내 위치만 보여 줍니다. 친구의 스크린샷 위치도 내 지도에 함께 그리도록, 개발자가 운영하는 서버를 거쳐 위치를 주고받게 했습니다. 앱에 서버 주소와 접속 키가 들어 있어 실행하면 자동으로 연결합니다.

같은 파티로 같은 레이드에 들어갔는지는 게임 로그로 판정합니다. 서버가 레이드를 만들면 application 로그에 그 레이드가 열린 게임 서버 세션이 남고, 메뉴로 돌아오면 프로필을 다시 고르는 줄이 남습니다. 같은 로그에서 서버 모드(PvE, PvP)와 내 계정 ID도 읽습니다. 파티가 매칭을 시작하면 push-notifications 로그의 알림에 파티 그룹 ID가 오고, 바로 뒤의 배정 알림에 같은 서버 세션이 옵니다. 앱은 이 둘을 서버 세션으로 맞춰 서버에서 `모드:파티 그룹 ID` 이름의 방에 들어가고, 스크린샷을 찍을 때마다 해석한 좌표를 올립니다. 처음에는 화면 오른쪽 아래의 레이드 ID(`shortId`)로 방을 나눴지만, 같은 레이드에서도 사람마다 마지막 글자가 달라 친구끼리 다른 방에 들어갔습니다. 파티 그룹 ID는 같은 파티의 같은 레이드에서만 같고 화면에 보이지 않는 값이라, 같은 레이드의 다른 파티나 방송 시청자가 방에 들어올 수 없습니다. 서버(ASP.NET Core SignalR 허브)는 같은 방의 다른 사람에게만 위치를 WebSocket으로 밀어 주므로, 내가 스크린샷을 찍지 않아도 친구가 찍는 즉시 내 지도에 나타납니다. 늦게 들어온 사람에게는 방의 마지막 위치를 넘겨 줍니다. 서버와 앱은 허브 계약을 Core DLL 한 곳에서 함께 읽어 어긋나지 않게 했습니다.

파티원의 닉네임은 push-notifications 로그의 파티 알림에서 계정 ID와 함께 읽습니다. 내 닉네임도 인벤토리 오류의 프로필 태그나 다른 사람이 가진 인식표에 드물게 남습니다. 앱은 같은 세션의 프로필 ID와 계정 ID를 대조하고, 저장된 이름이 없으면 지난 세션도 제한된 범위에서 백그라운드로 탐색합니다. 내 이름은 계정 ID와 함께 저장해 같은 계정에서만 복원하며, 현재 세션 로그, 파티원이 알려 준 이름, 지난 세션 로그, 저장값 순서로 선택합니다. 입장하거나 이름을 새로 알면 같은 방에 알립니다. 찾지 못하면 계정 ID 끝 네 자리로 표시하고, 나중에 알게 되면 그 자리에서 바꿉니다. 친구 마커는 레이드에서 처음 보인 순서대로 빨강, 주황, 노랑, 초록이고 내 마커는 친구 색과 겹치지 않는 밝은 회색입니다.

앱이 공개 배포되므로 앱에 든 접속 키는 비밀이 아닙니다. 키는 앱이 아닌 접속을 막고, 키를 바꿔 옛 판 앱의 접속을 끊는 데 씁니다. 사람을 거르는 일은 키가 아니라 파티 그룹 ID가 맡습니다. 서버는 허용할 모드를 정해 특정 모드의 공유를 끌 수 있습니다.

파티 목록은 위치 전송과 별개로 입퇴장 알림과 목록 조회로 갱신하고, WPF가 모든 보기 모드의 왼쪽 아래에 나를 먼저, 친구를 색 번호 순서로 표시합니다. 서버 운영자는 방 밖의 연결을 포함한 접속별 IP, 앱 버전, User-Agent, 계정 ID와 닉네임, 방 ID와 마지막 위치를 볼 수 있습니다. 참가 계정, 닉네임, 모드, 맵, 입퇴장 시각과 위치 전송 수는 SQLite에 기록해 통계로 쓰며 IP와 좌표는 저장하지 않습니다. 서버와 앱의 기존 계약은 유지하고 기능만 추가하므로 각각 갱신할 수 있습니다. 옛 서버에서는 목록과 이름 교환만 생략하고 받은 위치로 파티를 표시합니다.

공유는 부가 기능이라 서버가 꺼져 있거나 느려도 내 위치 표시가 기다리지 않게 경로를 나눴습니다. 공유 서비스는 스크린샷 이벤트에서 예외를 밖으로 내지 않고 서버 호출을 따로 돌리며, 친구 마커는 내 마커와 다른 요소에 그립니다.

## 개발 안내

Windows와 .NET 10 SDK 이상이 필요합니다. 앱은 .NET 8에서 실행되며, ViewModel의 partial 속성 생성(`LangVersion=preview`)에 최신 C# 컴파일러를 사용합니다.

```powershell
dotnet build TanukiTarkovMap.csproj
dotnet publish TanukiTarkovMap.csproj -c Release -r win-x64 --self-contained true -o publish
```

좌표 계산, 설정, 파일 감시, 위치 공유와 사이트 제어는 `packages/`에 포함된 TanukiTarkovMap.Core 패키지가 담당합니다. 프로젝트 파일이 이 패키지의 버전을 고정하고, `NuGet.Config`가 Core는 저장소의 `packages/`에서, 나머지 의존성은 NuGet.org에서 복원하므로 별도 계정이나 인증이 필요하지 않습니다. Core DLL은 Obfuscar로 난독화되어 있으며 공개 API와 JSON 계약은 그대로입니다. Releases의 설치 파일은 같은 태그의 소스로 빌드합니다.
