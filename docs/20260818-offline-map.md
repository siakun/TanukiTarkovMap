## 결론

이 문서는 사이트 사본을 재생하던 첫 Local 구현의 설계 근거입니다. 사본 방식(`archive/`, 사본 수집과
검사 도구, `MapArchive`)은 지금 제품과 저장소에 없습니다. 지금 Local은 사이트의 지도 데이터만 받아
앱의 미니맵이 그리며, 그렇게 바꾼 이유와 구조는 [로컬 맵 뷰어 설계](20260821-local-viewer-design.md)에
있습니다. 아래에서 Local 브라우저의 저장 공간 분리와 모드 전환 때의 위치 보관(`RequestContext`를
설명하는 부분부터 확인 조건까지)은 지금 Local에도 그대로 적용됩니다.

로컬 모드를 켜면 앱은 tarkov-market.com에 접속하지 않고, 함께 배포한 사본으로 맵을 엽니다.
주소는 온라인과 같고, 요청만 가로채 사본으로 답합니다. 화면에는 지도와 Levels, 선택한 진영의
추출구, 현재 위치와 방향만 남깁니다. 사이트가 죽어 있어도 레이드에 필요한 정보가 동작합니다.

## 왜 만들었는가

2026-08-17 하루에 두 번 겪었습니다. tarkov-market이 Pilot v2를 내면서 위치 표시가 끊겼고,
GitHub 장애로 버전 목록이 비었습니다. 이 앱은 레이드 중에 자기 위치를 보려고 켜는 도구인데,
남의 서버가 살아 있어야만 쓸모가 있는 상태였습니다.

## 먼저 실측한 것

만들기 전에 세 가지를 재 보았습니다. 하나라도 아니었다면 설계가 달라졌을 값들입니다.

**캐시만으로는 안 됩니다.** 맵 페이지를 정상으로 연 뒤 네트워크를 끊고 다시 열자 크롬 오류
페이지가 나왔습니다. 사이트가 문서를 캐시하지 않게 보내고, 서비스 워커도 스스로 등록을
해제합니다. 즉 우리가 저장하고 되돌려주는 계층이 필요합니다.

**사본만으로 페이지가 살아납니다.** 맵 페이지가 받은 응답을 전부 저장한 뒤, 그 저장분으로만
응답하고 나머지 요청은 모두 실패시켜 다시 열었습니다. SPA가 정상 마운트되고, `window.pilot`이
열리고, 실제 스크린샷 파일명을 넘기자 마커가 좌표와 회전각까지 갖고 생성됐습니다.

**맵에 타일 피라미드가 없습니다.** 확대와 이동을 반복해도 새 요청이 0개였습니다. 맵이 전부
벡터라 초기 로드분만 담으면 오프라인에서도 확대와 이동이 됩니다. 그래서 사본이 작습니다.
12개 맵 전체가 중복 제거 후 13MB입니다.

## 무엇을 고르고 무엇을 버렸는가

| 갈래 | 고른 것 | 버린 것과 이유 |
|------|---------|----------------|
| 자산 확보 | 사본을 앱과 함께 배포 | 런타임 수집은 첫 실행에 온라인이 필요하고, 자체 맵 구현은 맵별 좌표 변환과 뷰어를 새로 만들어야 함 |
| 주소 | 사이트 주소를 그대로 두고 요청만 가로챔 | 커스텀 스킴(local://)은 사이트 라우팅과 우리 주입 스크립트의 주소 판정을 모두 흔듦 |
| 사본에 없는 요청 | 404로 막음 | 네트워크로 흘리면 반쯤 온라인인 상태가 되어, 무엇이 최신인지 사용자도 우리도 알 수 없음 |
| 브라우저 저장 공간 | Local 진입마다 독립된 메모리 RequestContext 생성 | 공용 프로필은 최신 DB와 사본 자산을 섞고, Local 전용 디스크 프로필도 사본 갱신 뒤 이전 DB를 남김 |
| 저장 단위 | 내용 해시로 blob 하나, 맵별 색인이 가리킴 | 맵마다 통째로 담으면 공통 번들이 12번 반복되어 사본이 열 배로 커짐 |
| 전환 | 상단바의 수동 토글 | 자동 전환은 "왜 옛날 데이터가 보이지"를 사용자가 알 수 없게 만듦 |

## 지금 구조

```
tools/archive-maps.mjs        실제 브라우저로 맵 페이지를 열어 응답을 저장 (사람이 돌린다)
       ↓
archive/blobs, archive/maps   앱과 함께 배포되는 사본
       ↓
MapArchive                    주소 -> 본문과 MIME (본문은 한 번 읽어 메모리에 둔다)
       ↓
ArchiveResourceRequestHandlerFactory
       ↓
CefSharp 요청 가로채기         로컬 모드일 때만. 없으면 404
```

사본이 완전한지는 도구가 검사합니다. 브라우저가 미리 읽기로 받은 조각은 CDP가 본문을 주지
않는데, 맵의 지형이 바로 그 조각에 들어 있습니다. 이것을 빈 채로 담으면 앱은 200에 빈 본문을
돌려주고 사이트는 지형만 빠진 채로 뜹니다. 그래서 본문을 받지 못하면 같은 주소를 직접 한 번 더
받고, 그래도 못 받으면 어떤 주소인지 알리고 실패로 끝냅니다.

해시가 붙은 API의 `notModified` 응답도 담지 않습니다. 이 응답은 브라우저가 이미 가진 본문을
계속 쓰라는 지시라서, 새 브라우저에 돌려주면 데이터가 없습니다. 특히 정확한 해시 주소의
`notModified` 응답과 질의를 뗀 실제 본문이 함께 있으면 `MapArchive`는 정확한 주소를 먼저 골라
퀘스트와 스폰 마커를 비웁니다. 수집 도구는 본문을 해석해 이런 응답을 제외합니다.

사본을 다시 만든 뒤에는 `node tools/verify-archive.mjs`로 확인합니다. 이 도구는 앱과 같은 규칙으로
모든 요청을 사본에서 내고 없는 것은 실패시킨 채 맵 열두 개를 엽니다. 먼저 모든 색인의 본문을
읽어 `notModified` 응답을 거부하고, 브라우저에서는 바닥 맵과 퀘스트 목록이 채워졌는지, 마커
캔버스의 축소 표본에 실제 픽셀이 그려지는지 봅니다. 파일 수나 빈 마커 층의 존재만 확인해서는
앞선 두 결함을 잡지 못합니다.

Local 화면은 사이트가 모듈을 평가하기 전에 `sel_cats_map`을 진영별 추출구로 바꿉니다. 렌더링이
끝난 뒤 패널만 가리면 캔버스에 그린 퀘스트와 키 마커가 남기 때문입니다. Online에서 고른 마커
종류는 온라인 프로필에 남습니다. 저장 공간을 공유하던 버전이 남긴 백업도 Online 로드 시
복원합니다. 화면 요소는 Local 전용 CSS 규칙으로 감춰 "UI 요소 숨기기" 설정을 풀어도
Levels 외의 사이트 패널이 다시 나타나지 않습니다.

`node tools/verify-archive.mjs --local-core --maps shoreline`은 이 경계를 별도로 검사합니다. 퀘스트,
키, 스폰을 포함한 Online 선택을 먼저 만든 뒤 Local에서 추출구만 활성화되는지, PMC/SCAV 전환이
서로 다른 추출구를 그리는지, Levels와 위치/방향이 남는지, Online 복귀 뒤 원래 선택이 돌아오는지
확인합니다. 이 검사는 JS의 선택값 복원 호환 경로를 다루며, 앱의 RequestContext 분리 검사를
대신하지 않습니다.

로컬 모드를 켜면 사본 본문을 배경에서 미리 읽어 둡니다. 첫 페이지는 요청을 백 개 가까이 한꺼번에
보내는데, 그때 디스크를 처음 읽으면 응답이 늦어 사이트가 늦게 온 조각을 쓰지 못할 수 있습니다.
색인도 다 만든 뒤에 한 번에 공개합니다. CEF는 요청마다 다른 스레드에서 찾으므로, 채우는 중인
표를 읽히면 있는 항목을 없다고 답하게 됩니다.

설정의 실험적 기능에서 "로컬 맵 사용"을 켜면 상단바에 Online/Local 전환이 나타납니다. 사본이
없는 빌드에서는 전환 자체가 나타나지 않습니다. 켠 상태는 설정에 저장되고, 전환할 때마다
내장 브라우저를 교체해 같은 맵을 엽니다. 요청 처리기와 저장 공간은 CEF 브라우저를 만들기 전에
함께 정합니다.

따라가야 하므로 사용하지 않는다. Local의 메모리 저장 공간은 사본 갱신 때도 이전 DB를
물려받지 않게 하며, 사용자에게 이어 보여야 할 맵과 좌표는 앱이 보관한다.

Local 브라우저에는 빈 `CachePath`로 만든 별도 `RequestContext`를 연결합니다. 쿠키,
LocalStorage, IndexedDB와 HTTP 캐시는 Online 프로필에서 가져오지 않으며, Local을 나가면
그 임시 저장 공간을 해제합니다. Online으로 돌아갈 때는 기존 프로필을 다시 사용하므로
로그인과 사이트 설정이 유지됩니다. 이 수명은 `WebBrowserLifecycleBehavior`가 관리합니다.

브라우저 교체 중에는 `WebBrowserViewModel`이 현재 맵과 마지막 스크린샷을 보관합니다.
새 브라우저의 `about:blank`는 맵 이동으로 처리하지 않으며, 이전 브라우저의 로드 이벤트와
JavaScript 응답도 새 화면의 상태를 바꾸지 못하게 합니다. 같은 맵이 준비되면 마지막 위치를
다시 전달합니다. 교체 과정에서 웹 페이지의 방문 기록과 Local 페이지 안에서만 저장한 설정은
초기화되며, 앱의 진영과 확대 설정은 다시 적용합니다.

저장 공간과 위치 전달을 변경한 뒤에는 다음 조건을 함께 확인합니다.

- Online에서 사이트 데이터를 저장한 뒤 Local로 전환해 위치와 방향 표시 확인
- Local로 바로 시작한 경우와 Local에서 새로고침하거나 맵을 바꾼 경우 확인
- 위치를 전달하는 도중 모드를 연속 전환해 마지막으로 선택한 맵의 최신 좌표 확인
- Online 복귀 후 기존 로그인과 사이트 설정 유지 확인

## 한계

- 사본은 만든 시점의 사이트 자산이며 Local에서는 지도 코어만 표시합니다
- 사본 갱신은 릴리스에 실려 나갑니다. 사이트가 구조를 바꾸면 도구를 다시 돌려야 합니다
- 퀘스트, BattlePass, 키, Squad, 사용자 Layers, 눈금자, 마커 제안, Screenshot OCR은 Local에서
  표시하지 않습니다
- PVE/PVP 구분은 아직 없습니다. 사본은 캡처 시점의 모드 하나만 담고 있습니다

## 다시 검토할 조건

- 사이트가 맵을 타일 방식으로 바꾸는 경우. 초기 로드분만으로는 부족해지므로 확대 단계까지
  담는 수집이 필요해집니다
- 사본 크기가 설치 파일에 부담이 되는 경우. 맵별 선택 다운로드로 구조를 바꿉니다
- 원 사이트가 사본 배포에 이의를 제기하는 경우. 런타임 수집으로 옮기면 배포물에서 자산이
  빠지고 기능은 유지됩니다
