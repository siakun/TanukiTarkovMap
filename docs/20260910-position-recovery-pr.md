# 온라인 및 로컬 위치 표시 복구와 업데이트 내역 연결

사이트 업데이트 후 스크린샷 위치가 표시되지 않던 문제와, 온라인을 사용한 뒤 로컬 모드로
전환해도 위치 표시가 멈추던 문제를 수정합니다. 위치 전달과 방향 표시를 복구하고 로컬의
브라우저 저장 공간을 분리합니다. 게임 중 창 복원과 설정 안내도 함께 개선합니다.

## 웹사이트 업데이트 후 위치가 표시되지 않은 원인

기존 앱은 사이트가 전역으로 제공하던 `window.pilot.positionFromScreenshot()`에 파일명을
전달했습니다. 이 경로가 없는 페이지에서는 스크린샷 파일을 감지해도 좌표를 전달하지 못했습니다.
Lighthouse에서 관찰된 증상도 이 연동 경로의 변경과 관련되며, 맵 이름이나 스크린샷 키만
고쳐 해결할 문제가 아니었습니다.

`pilot-bridge.js`에서 사용 가능한 함수를 확인해 이전 전역 Pilot과 Nuxt의 Pilot 서비스를
지원합니다. 새 서비스에는 파일명의 좌표를 파싱해 `positionUpdate()`로 전달합니다.
지도별 좌표 변환은 렌더 중인 지도 객체를 사용하고, 방향은 파일명의 회전값으로 계산합니다.

함수가 반환됐다는 이유만으로 전달을 끝내지 않습니다. 지도 로딩이 늦으면 함수가 있어도
마커가 입력을 받지 못할 수 있으므로, 플레이어 좌표가 입력과 일치하고 위치 마커와 방향
표시가 준비된 뒤에만 완료로 처리합니다. 그전까지는 대상 맵의 최신 입력만 보관해 다시 보냅니다.

같은 주소에서 지도 컴포넌트만 교체될 수 있으므로 지도 객체를 주소별로 캐시하지 않습니다.
현재 Vue 트리에서 지도를 찾고 마지막 좌표가 여전히 표시되는지도 주기적으로 확인합니다.
스크립트가 살아 있어도 위치가 초기화됐으면 다시 전달합니다. 이전 지도에서 시작한 요청이나
새 요청보다 늦게 끝난 응답은 방향 표시를 바꾸지 못하게 합니다.

## 로컬 모드에서도 위치가 표시되지 않은 원인

기존 로컬 모드는 같은 브라우저에서 요청 처리기만 바꾸고 새로고침했습니다. 페이지 주소도
같았으므로 Online과 Local이 쿠키, LocalStorage, IndexedDB와 HTTP 캐시를 공유했습니다.
사본 파일은 저장 시점의 사이트였지만, 페이지가 읽는 데이터는 온라인에서 갱신된 상태일 수
있었습니다.

온라인에서 저장한 IndexedDB의 데이터 해시로 로컬 사본에 없는 `/api/be/cache` 응답을
요청하면 404가 발생했습니다. 이어지는 지도 초기화가 실패해 Pilot 함수 호출은 반환돼도
위치 마커가 생성되지 않았습니다. 빈 저장 공간에서는 로컬 위치 표시가 동작했고, 온라인
사용 후 전환한 환경에서 실패했습니다. LocalStorage만 비워서는 해결되지 않았으며,
재현용 브라우저의 IndexedDB를 비웠을 때 복구되는 것을 확인했습니다.

모드 전환 시 내장 브라우저를 교체합니다. Online은 기존 프로필을 사용하고 Local은 별도의
메모리 `RequestContext`에서 시작합니다. Local을 나가면 임시 저장 공간을 해제하므로 다음
진입이나 사본 갱신 때 이전 DB가 섞이지 않습니다. 온라인의 DB를 지우거나 사본에 없는 요청을
네트워크로 보내는 방식은 사용하지 않습니다.

브라우저를 교체하는 동안 현재 맵과 마지막 위치는 ViewModel에 보관합니다. 준비용
`about:blank`와 이전 브라우저에서 늦게 도착한 이벤트 및 응답은 새 화면의 전달 대기를
지우지 못하게 합니다. 같은 맵이 준비되면 마지막 입력을 다시 전달합니다.

## 방향 표시가 사라진 원인과 수정

방향 스크립트를 한 번 주입하는 방식은 새로고침, SPA의 뒤로/앞으로 이동, 지도 DOM 교체를
처리하지 못했습니다. 앱이 설치 여부를 알고 있어도 실제 페이지에서 함수나 표시 요소가
사라질 수 있었습니다.

주기 확인과 스크린샷 전달에서 같은 복구 경로를 사용합니다. 방향 스크립트와 Pilot 브리지의
응답을 확인하고 필요하면 재주입합니다. 페이지 내부에서도 DOM 교체를 감지해 화살표와
스타일을 복구하며, 중복 주입 시 기존 관찰자를 정리합니다. 위치 동그라미의 좌표는 유지하고
화살표만 원 바로 앞에 배치합니다.

스타일 요소의 ID가 남아 있어도 내용이 비거나 스타일이 비활성화되면 복구합니다. CSS 규칙이
삭제된 경우도 같은 확인 경로를 거치며, 정상 상태에서는 DOM을 반복해서 덮어쓰지 않습니다.

## 함께 변경한 동작

- 항상 위 핀이 꺼진 상태에서 맵 창을 다시 표시할 때 일반 창 중 앞으로 올립니다. 창을 표시하는 첫 단계부터 게임 포커스를 가져오지 않게 합니다.
- 최소화된 창도 단축키 첫 입력에서 복원합니다. WPF의 `IsVisible`이 참이어도 실제 창은 최소화돼 보이지 않을 수 있으므로 `WindowState`를 함께 확인합니다.
- 설정에서 창 표시/숨김과 위치 갱신 키를 구분하고, 트레이 숨김과 항상 위 고정을 설명합니다.
- 군즈 정보를 PvE 최근 목격 제보로 안내합니다. 새 설정은 기본 비활성화하며 기존 설정은 유지합니다. 꺼진 동안에는 제보를 조회하지 않습니다.
- Local 화면은 지도 코어 정보만 남기며, UI 요소 숨기기가 남은 패널에도 적용되도록 합니다.
- 프로젝트 버전과 릴리스 태그가 일치하는지 검사하고, 버전별 업데이트 내역을 GitHub 릴리스 본문과 Velopack 패키지에 함께 넣습니다.

## 검증

원인 조사에서는 온라인 사용 후 로컬 전환에 따른 IndexedDB 충돌을 재현했습니다. 위치 브리지의
이전/새 서비스 처리, 새로고침과 뒤로/앞으로 이동에 따른 복구, 방향 표시의 크기와 회전 조합은
별도 브라우저 환경에서 확인했습니다. 창 복원 시 포커스 유지도 별도로 확인했습니다.

- [x] 최종 변경의 Debug 및 Release 빌드
- [x] `node tools/verify-map-recovery.mjs --archive archive`: DOM 손상, 같은 주소의 지도 교체, SPA 이동과 응답 순서 역전, 이전/새 Pilot 연동, 저장 공간 분리 및 네트워크를 차단한 사본의 위치 표시
- [x] 현재 온라인 Lighthouse와 저장된 Lighthouse 및 Reserve에서 위치와 방향 표시
- [x] 배포 메타데이터 검사: 정상 버전 통과, 버전 불일치 및 내역 파일/목록 누락 차단
- [ ] 최종 WPF 앱에서 온라인 사용 후 Local 전환 및 위치 표시
- [ ] 최종 WPF 앱에서 로딩 중 스크린샷 촬영과 모드 연속 전환
- [ ] 최종 WPF 앱에서 최소화 상태의 단축키 복원 및 실제 게임 포커스 유지

저장 공간 분리를 반영한 최종 WPF 앱은 아직 실행 검증하지 않았습니다. 기존 검증을 최종
변경 전체의 통합 검증으로 간주하지 않습니다.

재현 검사는 저장소에 남기고 PR과 릴리스 워크플로에서 실행합니다. 실패하면 릴리스 작업을
시작하지 않습니다. 저장 공간 검사는 별도 Chromium 컨텍스트에서 수행하므로 WPF와 CEF의
컨트롤 교체까지 검증했다고 해석하지 않습니다.

## 영향과 한계

모드를 바꿀 때 웹 페이지의 방문 기록과 Local 페이지 안에서만 저장한 설정은 초기화됩니다.
앱의 진영과 확대 설정은 다시 적용하며 Online의 프로필은 유지합니다. 사이트가 지원하는
Pilot 함수나 지도 객체의 구조를 다시 바꾸는 경우에는 어댑터 수정이 필요할 수 있습니다.
스크립트 자동 복구가 앞으로의 모든 사이트 변경을 처리한다는 의미는 아닙니다.
