# 오프라인 맵 사본

이 폴더는 tarkov-market.com의 맵 페이지가 내려보낸 응답을 그대로 저장한 사본입니다. 앱의
로컬 모드는 브라우저 요청을 가로채 여기 담긴 응답으로 답해, 사이트가 죽어 있어도 지도와
Levels, 진영별 추출구, 현재 위치와 방향이 동작하게 합니다.

내용의 저작권은 tarkov-market.com에 있습니다. 이 폴더의 파일은 우리가 만든 것이 아니라
그 사이트에서 받은 것을 담아 둔 것입니다.

## 구조

```
blobs/<sha1>        응답 본문. 같은 내용은 맵이 달라도 한 번만 저장됩니다
maps/<맵ID>.json    { 주소: { blob, mime, status } }
manifest.json       만든 시각, 맵 목록, 맵별 크기
```

주소를 그대로 열쇠로 씁니다. 맵별 데이터는 사이트가 `api/be/map-doc?map=<맵ID>`처럼 주소로
갈라 두었으므로 맵끼리 섞이지 않습니다.

## 다시 만들기

사이트 구조가 바뀌거나 맵이 추가되면 다음 명령으로 사본을 새로 만듭니다. 손으로 파일을
모으지 않습니다.

```
node tools/archive-maps.mjs --out archive
```

맵 하나만 갱신하려면 `--maps lab,customs`처럼 지정합니다. 도구는 실제 브라우저로 페이지를
열어 받은 응답을 저장하므로, 사이트가 무엇을 필요로 하는지 우리가 알 필요가 없습니다.
단, 실제 데이터 대신 `notModified: true`가 든 응답은 저장하지 않습니다. 이미 받은 데이터를
브라우저 캐시에서 쓰라는 지시라서, 캐시가 없는 로컬 모드에서는 실제 데이터를 대신할 수 없기
때문입니다.

만든 뒤에는 반드시 확인합니다. 파일 수만으로는 응답이 빈 채로 담긴 상태를 잡지 못합니다.

```
node tools/verify-archive.mjs
node tools/verify-archive.mjs --local-core --maps shoreline
node tools/verify-map-recovery.mjs --archive archive
```

이 도구는 먼저 모든 색인의 본문에서 `notModified` 응답을 찾습니다. 그런 응답이 없으면 네트워크를
완전히 막고 사본만으로 맵 열두 개를 열어, 바닥 맵이 그려지는지, 퀘스트 목록이 채워졌는지, 마커
캔버스의 축소 표본에 실제 픽셀이 그려지는지 봅니다. `--local-core` 검사는 지정한 맵에서 Local 전용
UI와 마커 축소, PMC/SCAV 전환, Levels, 위치와 방향, Online 선택 복원까지 확인합니다. 하나라도
실패하면 종료 코드 1로 끝납니다.

`verify-map-recovery.mjs`는 창 없이 별도 브라우저 저장 공간에서 위치와 방향 연동을 검사합니다.
스크립트가 살아 있어도 지도가 입력을 받지 못하는 경우와 온라인 데이터가 로컬로 섞이지 않는
조건을 확인합니다. 이 검사는 PR과 릴리스에도 연결돼 있으며 실제 WPF 모드 전환 검증과는 구분합니다.

수집 도구는 페이지가 실제로 받은 응답에 더해, css가 가리키는 폰트와 이미지도 채웁니다.
브라우저는 그 규칙이 쓰일 때만 그런 자원을 받아 오므로, 맵 화면에서 안 쓰이는 이탤릭 폰트나
한국어 서브셋은 페이지를 열어도 요청되지 않아 그냥 두면 사본에서 빠집니다.

[오프라인 맵 설계](../docs/20260818-offline-map.md)에 있습니다.
